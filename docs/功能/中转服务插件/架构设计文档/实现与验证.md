# 实现与验证

## 模块

- `index.mjs`：插件入口，注册供应商、登录及宿主钩子。
- `src/config.mjs`：校验地址与选项，账号地址优先于包级 `baseURL`。
- `src/transport.mjs`：账号凭据读取、Responses 转发和有界查询。
- `src/errors.mjs`：安全错误分类与重试时间校验，不暴露上游正文。
- `src/models.mjs`：模型筛选、分页与元数据配置。
- `src/usage.mjs`：将服务用量转换为宿主窗口。
- `assets/logo.svg`：图标来源，通过 `bun run sync-icon` 同步包内图标。

纯站点地址自动补 `/v1`，已指定的 API 路径保持不变。登录、已保存账号、包配置及全部请求共用这一规范化规则。

钱包只返回原生余额，不创建重复窗口，可与当前密钥或订阅额度同时展示，不与它们相加。`quota_limited` 模式仅采用密钥限制，不启用残留订阅数据；其他情况下有有效订阅信息才展示订阅额度和有效期。订阅只有有效期时不创建进度条。

插件输出的金额统一为两位小数；不足 0.01 的非零金额用边界表示，例如 `<$0.01`、`>-$0.01`，避免显示成零。真实限额的 `amount`、`limit` 和 `unit` 保留原始精度，交由宿主绘制进度条和显示数额；格式化不影响额度判断。未知已用量不填零。今日、累计和流量信息均为 `aside` 辅助窗口，不影响路由。

窗口标题使用宿主已支持且语义匹配的词条，如 `Today`、`Total`、`Usage` 和 `1 day`，由 Magpie 按界面语言翻译。自定义选项、错误及部分标题仍使用英文；当前插件接口未提供界面语言或翻译注册入口。`req` 表示请求数，`tok` 表示 Token 数。

查询仅访问配置地址的指定端点，拒绝重定向；每个响应及累计模型目录最多 4 MiB，模型最多 20 页。同地址、同 Key 的相同在途查询合并，完成后不缓存。生成请求保留正文、流式响应及取消信号。

## 配置示例

在 Magpie 插件包的 `options` 中设置，修改后重载插件：

```json
{
  "queryTimeoutMs": 15000,
  "showTraffic": true,
  "excludeModels": [],
  "modelOverrides": {
    "your-model-id": {
      "name": "Custom model name",
      "limit": { "context": 200000, "output": 32000 },
      "temperature": false,
      "reasoning": true,
      "toolCall": true,
      "imageInput": true,
      "reasoningLevels": ["low", "medium", "high"]
    }
  }
}
```

容量和档位仅演示格式，应按服务提供的信息填写。覆盖不会创建模型或绕过 GPT-5/6 筛选；`reasoning: false` 时不提供推理档位。

能力取值依次采用显式覆盖、宿主已有模型信息和保守默认。没有依据时不声明采样控制、推理、工具调用或图片输入；明确配置推理档位可开启推理，但不能覆盖已有的 `reasoning: false`，此时需明确设置 `reasoning: true`。目录刷新不执行付费生成，也不根据一次失败永久隐藏模型。

对本次已验证的服务账号，可按需配置以下模型能力；这是特定服务的配置示例，不是所有同名模型的通用保证，也不随包自动启用：

```json
{
  "modelOverrides": {
    "gpt-6-luna": {
      "temperature": false,
      "toolCall": true,
      "imageInput": true
    }
  }
}
```

此示例不编造上下文容量和推理档位。工具和图片验证范围见[服务能力](../../../服务能力.md)。

`queryTimeoutMs` 范围为 1000–60000 毫秒，仅限制查询，不限制生成时长。宿主保存的流量开关优先于 `showTraffic`。

## 离线检查

```bash
bun test
bun run check
```

测试使用模拟上游；包检查核对语法、入口、身份及图标一致性，不代表真实服务或桌面安装已验证。

官方宿主检查使用独立临时目录和合成凭据，需要先取得宿主源码：

```bash
gh api repos/yetone/magpie/contents/internal/plugin/host.js \
  -H 'Accept: application/vnd.github.raw+json' > /tmp/magpie-host.js
bun run test:host /tmp/magpie-host.js
```

## 真实服务检查

接口实测结果、参数限制和插件支持边界见[服务能力](../../../服务能力.md)。

```bash
bun run test:relay --help
```

诊断脚本读取 `TET_BASE_URL` 和 `TET_API_KEY` 环境变量，不读取凭据文件。Key 应通过终端不回显输入注入，不放入命令历史或仓库。

- `bun run test:relay`：只查询模型与用量。
- `bun run test:relay --allow-http`：明确允许 HTTP 明文连接。
- `bun run test:relay --generate --model your-model-id`：额外检查非流式和流式 Responses，最多发送两次生成请求，可能产生消费；HTTP 服务还需加 `--allow-http`。

诊断不输出 Key、响应正文或生成文本，也不自动重试。默认生成检查只覆盖文本 JSON 和 SSE。

显式生成模式可增加能力检查，全部通过时最多发送五次生成请求：

```bash
bun run test:relay --generate --model your-model-id --tools --structured
```

`--tools` 额外检查函数调用及结果回传（两次请求），`--structured` 额外检查严格 JSON Schema 的基本行为（一次请求）；两者都必须与 `--generate --model` 一起使用，HTTP 仍需 `--allow-http`。任一步失败即停止，不重试或自动更换模型。结构检查和工具参数必须符合预期，HTTP 200 本身不算能力验证通过。

诊断错误区分认证、限流、上游、模型不可用、超时和网络故障，保留状态码及经过校验的 `Retry-After`，不展示上游原文。模型不可用只识别有界 JSON 错误中的固定 `model_not_found` 代码；其他错误不猜测原因。图片、Compact、采样控制和服务端存储仍不属于正式诊断检查。

工具结果回传使用显式历史，不依赖 `store` 或 `previous_response_id`。官方宿主沙箱核对显式多轮历史与工具结果在宿主、插件和上游边界保持不变；这不代表已验证实际桌面 SDK 构造请求的全部行为。转发层不删除响应 ID、不改写历史、不把 Compact 请求改为普通生成。

本机测试地址等备忘放在已被 Git 忽略的 `docs/local/`，不随源码或发布包交付。
