# TET for Magpie

Magpie 的 TET 中转供应商插件，支持 GPT-5/6 模型发现、OpenAI Responses 转发、余额与用量查询。无运行时依赖，无需构建。

## 安装

在 Magpie 插件页面添加：

```text
github:xgxg-mdl/magpie-tet#main
```

或使用 CLI：

```bash
magpie plugin add github:xgxg-mdl/magpie-tet
magpie plugin login tet
```

## 使用

在 **TET** 供应商中填写 **API base URL** 和 **API Key**，随后选择 `tet/<模型 ID>`。

填写站点地址（如 `https://relay.example`）时自动使用 `/v1`；也可填写完整 API 地址，已有 `/v1` 或自定义路径会保留。建议使用 HTTPS；HTTP 会明文传输 Key 和请求内容。

插件通过 TET 中转站的 `/models` 获取模型、`/responses` 转发请求、`/usage` 查询余额与用量。目前支持 GPT-5/6 文本模型，不支持 Claude/Gemini 专用协议、图片生成、音频或实时模型。

供应商设置中的 **Show traffic statistics** 可控制流量统计展示。

### 管理台分组额度

推荐使用 **TET 账号登录（自动获取 Key）**：填写管理台地址、账号和密码，网关 API 地址可留空使用登录响应中的 `codexGatewayUrl` 或 `gatewayPublicBaseUrl`，也可显式覆盖。插件自动取得该用户的网关 Key；缺失时读取 `/api/auth/profile/gateway-config`。管理台与网关可使用完全不同的地址，认证分别发送，不从管理台地址猜测网关地址。账号登录要求服务端返回用户标识、有效会话到期时间和可用 Key。

账号登录使用 Magpie 的会话认证存储和 `auth.refresh` 调度，模型调用仍使用网关 Key。会话临近到期时先请求 `/api/auth/me`；只有响应明确返回有效的新 token 或更晚的到期时间才视为续期，普通用户信息响应不会被当作续期成功。未续期或收到 401 时使用已保存密码重新登录。新的账号 Key 随续期响应更新，但网关地址保持用户确认的值；身份发生变化则要求重新登录。这里并未使用服务端未声明的 refresh-token 接口，宿主 `refresh` 字段保存的是稳定账号标识。

纯 **TET API key** 和下面的旧绑定方式继续兼容，不自动迁移已有登录项。需要切换时重新选择账号登录。

需要查看管理台的周期额度时，登录方式选择 **TET API Key + 管理台额度**：

1. 填写网关 API 地址和独立的管理台地址，后者不是网关 API 地址。
2. 输入管理台账号和密码，无需选择或固定绑定分组。
3. 填写该登录项使用的 TET API Key。

每次刷新重新获取管理账号可见的全部分组及关联上游，跟随分组新增、删除、改名与上游迁移。旧认证中的固定分组字段会被忽略，有效会话无需重新登录；零分组也可以正常登录和查看钱包。

插件使用原生扁平双列窗口：Key 消费和流量在前，各分组先展示相邻的 `5h` 和 `7d` 进度，再展示纯文字「并发」和可用重置。额度保留在每个账号内部，不提供跨账号额度合计。所有分组指标均带来源名称，账号方案标签不再混入分组信息；宿主不支持独立分组标题，使用名称前缀区分归属。多个上游的额度分别显示，优先采用可读名称，缺少或重名时才使用上游编号，不累加百分比或重置次数。分组没有上游时保留并发并显示「暂无额度来源」。到期提示附在重置次数下方，由 Magpie 按界面时区显示。真实的 Key 和订阅限额仍保留并优先展示。

管理台数据属于登录用户可见的来源，不代表当前 Key 的独占额度或实际路由归属。并发是最近一次读取的整个分组快照，可能包含其他 Key 的请求；周期额度和重置次数按上游读取，均仅供展示，不参与路由。金额和请求数完整显示，Token／TPM 使用紧凑格式。不会导入管理台已有的历史趋势；宿主协议没有独立的指标来源 ID 或历史清理接口，来源变化后的原生历史曲线隔离不作保证。

管理台数据随现有用量刷新读取，不额外轮询。单轮请求量为「分组列表页数 + 2 × 不同上游数」，不含登录、认证失败后的单次重试和独立的钱包查询。同一管理会话的同时刷新共享整轮在途请求，跨分组的相同上游只读取一次；最多同时查询两个上游（四个 HTTP 请求）。自动登录、列表分页和后续上游查询共用最多 5 秒的总预算。查询完成后不跨刷新缓存额度，列表失败不显示旧分组，上游查询失败仅影响该项；并发缺失或上限无效时不推断为零或无限。并发快照可能漏掉两次刷新间的瞬时峰值，也不代表请求成功率。

为支持自动重新登录，管理台账号、密码和会话保存在该账号的宿主认证数据中，与网关 Key 分开使用，不写入日志或用量结果。距离会话到期不足 5 分钟或已经到期时，先检查 `/api/auth/me` 是否能明确续期，再回退重新登录；服务端提前返回 401 时也会恢复会话，并将失败查询重试一次。并发刷新合并登录，失败后退避 30 秒。新会话通过 Magpie 的账号作用域认证接口保存。账号登录由宿主续期调度触发；旧 API Key 登录项由插件在用量读取中恢复，不额外创建后台轮询。旧登录项未保存密码，需要重新使用此方式登录一次才能启用自动恢复。管理台查询失败不会将有效的 API Key 标为过期，也不会隐藏正常的钱包和消费数据。改回 **TET API key** 登录方式可移除管理台绑定。

管理台接口按上游账号查询额度，列表的分组 ID 不能直接当成查询 ID。插件内部使用最新列表返回的上游 ID 查询，不将内部查询标识当作单上游场景的可见标签。同一来源可能被多个 Key 的登录项重复展示，不能将这些显示项理解为多份独立额度。

已过重置时间的非零读数、降级或超过 15 分钟未更新的额度读数仅显示状态，不生成百分比历史点。新读取明确返回零用量时仍显示 `0%`，但移除已失效的重置时间及周期推算；缺失读数不会补零。重置次数为零会明确显示。管理台用量查询最多等待 5 秒（配置的查询超时更短时采用更短值），超时以辅助状态展示，保留已成功读取的钱包和消费。此模式需要支持动态登录问题和密码问题的 Magpie；无需管理台数据的账号继续使用原登录方式。

## 配置

一般无需额外配置。高级选项在 Magpie 插件包的 `options` 中设置，修改后重载插件：

| 选项             | 默认值  | 用途                               |
| ---------------- | ------- | ---------------------------------- |
| `queryTimeoutMs` | `15000` | 模型及用量查询超时，单位毫秒       |
| `showTraffic`    | `true`  | 流量统计开关初始值                 |
| `excludeModels`  | `[]`    | 按模型 ID 隐藏模型                 |
| `modelOverrides` | `{}`    | 配置模型名称、容量、能力和推理档位 |

模型目录不保证所有能力可用。插件优先采用显式配置和宿主已有信息，未知能力默认不声明；已核实模型的配置示例见维护文档。
